**外部アクセス** を使用すると、ローカルのコマンドラインプログラムや [MCP](https://modelcontextprotocol.io/) 対応の AI
クライアントが、[sctl](https://github.com/scriptscat/sctl) を通じて ScriptCat のスクリプトを管理できます。

```text
AI client ── stdio MCP ──▶ sctl mcp ── local control API ──▶ sctl serve ── WebSocket ──▶ ScriptCat
CLI ────────────────────────────────────────────────────────▲
```

`sctl serve` は、明示的に起動する必要がある独立したローカルデーモンです。`sctl mcp` と要求コマンドは決して自動的に
起動しません。ソース開示や書き込みが許可されるかどうかは、常に ScriptCat のポリシーとブラウザの確認 UI が決定します。
外部プログラムが自分の要求を承認することはできません。

:::warning リスナーはデフォルトでローカルです
sctl はデフォルトで `127.0.0.1` で待ち受けます。`--listen-address` を明示的に指定した場合のみ、別のインターフェースで
待ち受けます。`ws://` は業務トラフィックを暗号化せず、リモートクライアントごとの分離もないため、信頼できるネットワーク上
でのみデフォルト以外のアドレスを使用してください。拡張機能とデーモンは、それでもワンタイムのペアリングコードによって
長期キーを確立し、以降の接続では相互認証を使用します。
:::

## 1. sctl をインストールする

次の 1 つのコマンドで最新リリースをインストールします — macOS と Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/scriptscat/sctl/main/scripts/install.sh | sh
```

または Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/scriptscat/sctl/main/scripts/install.ps1 | iex
```

インストーラーは、プラットフォーム用のハイフン名のリリースアーカイブ `sctl-<version>-<os>-<arch>.<ext>` をダウンロードし、
同じリリースの `checksums.txt` に対して sha256 を検証して、`sctl` を `~/.local/bin`（macOS/Linux）または
`%LOCALAPPDATA%\sctl\bin`（Windows）にインストールします。`SCTL_VERSION` は特定のバージョンを固定し、`SCTL_INSTALL_DIR`
はインストールディレクトリを上書きします。インストールディレクトリが `PATH` にない場合、インストーラーはプラットフォーム
に応じた正確な `PATH` のヒントを表示します — シェルプロファイルやユーザーの `PATH` を自動的に編集することはありません。

sctl は単一の実行ファイルです。[GitHub Releases](https://github.com/scriptscat/sctl/releases) にプラットフォーム用の
公開アーカイブがあれば、ダウンロードして解凍し、`sctl`（Windows では `sctl.exe`）を `PATH` に追加することもできます。

```bash
sctl version
```

ソースからのビルドは、バージョン、コミット、ビルド時刻のメタデータが注入されたリリースビルドと区別するために
`0.0.0-dev` と報告します。これは ScriptCat への接続を妨げません。リリースがない場合、コントリビューターは
[sctl リポジトリ](https://github.com/scriptscat/sctl)からビルドできます。

## 2. デーモンを起動して登録する

登録は一度だけの手順です。その後、CLI とすべての MCP クライアントは信頼できる拡張機能-デーモンチャネルを共有します。
個別にペアリングする必要はありません。

### 2.1 データディレクトリを選択する

デーモン、CLI、MCP プロセスは同じデータディレクトリを使用する必要があります。そこには長期ペアリングキー、ローカル
コントロールトークン、ログが保存されます。現在のユーザーにプライベートな絶対パスを選択してください:

```text
/absolute/path/to/sctl-data
```

すべての sctl プロセスに同じ環境変数を設定します:

```bash
export SCTL_DATA_DIR=/absolute/path/to/sctl-data
sctl serve
sctl status
sctl mcp
```

明示的な `--data-dir` は環境変数より優先されます。

`--data-dir` も `SCTL_DATA_DIR` も設定されていない場合、sctl はプラットフォームのデフォルトのユーザーアプリケーションデータ
ディレクトリを使用します。データディレクトリをリポジトリや共有同期フォルダーに置かないでください。また、その
`pairing.key` や `control.token` を AI モデルに渡さないでください。

### 2.2 デーモンを起動する

ターミナルでこれを実行し、プロセスを稼働させ続けます:

```bash
sctl serve
```

デフォルトのアドレスは `ws://127.0.0.1:8643` です。デーモンは `connect`、`status`、他の CLI コマンド、`sctl mcp` によって
自動起動されることはありません。永続的に使用するには、オペレーティングシステムのユーザーサービス管理機能で上記の
コマンドを実行してください。

すべてのネットワークインターフェースで明示的に待ち受けるには、次を実行します:

```bash
sctl --listen-address 0.0.0.0:8643 serve
```

デーモンホストでは、同じ `--listen-address` を `connect`、`status`、他の CLI コマンド、`sctl mcp` に渡します。
ScriptCat の **sctl アドレス** 設定には、拡張機能が実際に到達できるアドレスを入力します。例: `ws://192.168.1.10:8643`。
`0.0.0.0` は入力しないでください。

### 2.3 ScriptCat で有効化してペアリングする

1. ScriptCat で **設定 → ツール → 外部アクセス** を開き、スイッチをオンにします。
2. **sctl アドレス** がデーモンと一致することを確認します。通常はデフォルトの `ws://127.0.0.1:8643` のままにします。
3. `sctl serve` を実行したまま、別のターミナルで次を実行します:

   ```bash
   sctl connect
   ```

4. 「sctl を登録」ダイアログに 8 文字のターミナルコードを入力します。
5. 接続を確認します:

   ```bash
   sctl status
   ```

ステータスに接続された拡張機能とデーモンバージョンが表示されるはずです。

:::warning ペアリングコードはターミナルのみです
コードは `A1B2-C3D4` のような形式で、2 分後に失効し、一度だけ使用できます。WebSocket 経由で拡張機能に送信されることは
ありません。AI チャット、issue、ログ、MCP 設定に貼り付けないでください。失効した場合は `connect` を再度実行してください。
:::

## 3. 権限と確認 {#permissions}

| 機能 | デフォルトの動作 |
|---|---|
| スクリプトの一覧表示とメタデータの読み取り | 直接返す |
| スクリプトソースの読み取りまたは検索 | **ソース読み取り** ポリシーに従う |
| スクリプトのインストール、編集、有効化、無効化、削除 | **書き込み** ポリシーに従う |

どちらのポリシーにも「承認が必要」（デフォルト）と「直接許可」があります。

「承認が必要」の場合、要求によりブラウザに確認ページが開きます。拒否、一度だけ許可、「このセッションで許可」を選択
できます。セッション許可はスクリプトと操作の種類ごとにキー付けされ、ブラウザの再起動、拡張機能の再読み込み、または
外部アクセスの停止時にクリアされます。要求は判断がなければ 5 分後に失効します。要求元の切断や `Ctrl-C` も要求を無効にします。

「直接許可」は、そのクラスの操作の確認ページをスキップします。ソースには API キー、Cookie、その他の機密情報が含まれる
可能性があり、書き込みはスクリプトを直接変更できるため、そのリスクを受け入れる場合にのみ有効にしてください。

## 4. コマンドラインでの使用

```bash
sctl get                         # スクリプトを一覧表示
sctl get <uuid>                  # メタデータを読み取り
sctl get <uuid> -o source        # 完全なソースを出力
sctl get <uuid> -o source --lines 20-80
sctl grep <uuid> "fetch("         # ソースのリテラル検索
sctl grep <uuid> "pattern" -E    # 正規表現
sctl install <url|file>
sctl edit <uuid> --replace OLD --with NEW
sctl enable <uuid>
sctl disable <uuid>
sctl delete <uuid>
sctl status
```

`grep` はデフォルトでリテラル検索です。`-E` で正規表現、`-i` で大文字小文字を無視、`-C N` でコンテキスト追加、`-m N` で
一致数を制限できます。一致なしは成功とみなされ、終了コード 0 で終了します。

`edit` はコンテンツアンカー方式で、行番号ベースではありません。各 `oldText` はデフォルトで正確に 1 回出現する必要が
あります。`--replace-all` はすべての一致を置き換えます。`-f <file>` で `{oldText,newText,replaceAll?}` 配列を渡すことも
できます。拡張機能に送信されるのは編集内容のみで、ソース全体を先に読み取ったりアップロードしたりする必要はありません。

書き込みとソース開示はブラウザの判断を待ちます。CLI の終了コード:

| 終了コード | 意味 |
|---|---|
| `0` | 承認され成功、または読み取りコマンドが正常に完了 |
| `1` | ユーザーが要求を拒否 |
| `2` | 要求が失効、`Ctrl-C` でキャンセル、または拡張機能が切断 |
| `3` | 引数、接続、スクリプトの欠落などのその他のエラー |

すべてのオプションについて `sctl <command> --help` を実行してください。

## 5. AI クライアントを接続する（MCP）

まず `sctl serve` が実行されており、`status` が接続された拡張機能を報告していることを確認します。次に、MCP クライアントが
別の `sctl mcp` プロセスを起動するように構成します。GUI クライアントでは絶対パスのバイナリとデータパスを使用します:

```json
{
  "mcpServers": {
    "scriptcat": {
      "command": "/absolute/path/to/sctl",
      "env": {
        "SCTL_DATA_DIR": "/absolute/path/to/sctl-data"
      },
      "args": [
        "mcp",
        "--name",
        "my-ai-client"
      ]
    }
  }
}
```

多くの GUI アプリケーションは `~`、`$HOME`、シェル式を展開しません。`--name` は監査ラベルであり、認証された ID や
認可境界ではありません。MCP の stdout はプロトコルフレーム用に予約されています。sctl を stdout にバナーを出力する
スクリプトでラップしないでください。

現在のツール:

| ツール | 目的 | 確認ポリシー |
|---|---|---|
| `scripts_list` | スクリプトの概要を一覧表示 | なし |
| `scripts_metadata_get` | 1 つのスクリプトのメタデータを読み取り | なし |
| `scripts_source_get` | uuid とオプションの行ウィンドウでソースを読み取り | ソース読み取りポリシー |
| `scripts_source_grep` | ソースを検索して一致する行を返す | ソース読み取りポリシー |
| `scripts_install_request` | スクリプトのインストールを要求 | 書き込みポリシー |
| `scripts_edit_request` | コンテンツアンカー方式の編集を要求 | 書き込みポリシー |
| `scripts_toggle_request` | 有効化または無効化を要求 | 書き込みポリシー |
| `scripts_delete_request` | 削除を要求 | 書き込みポリシー |

## 6. 監査と取り消し

- 外部アクセスカードの「監査ログを表示」で、このソースにフィルタリングされたログページが開きます。
- `sctl status` はデーモンバージョン、拡張機能の接続状態、最近のセキュリティイベントを表示します。`-o json` は完全なイベントを返します。
- 「外部アクセスを停止」は切断し、拡張機能側のペアリング状態を削除し、セッション許可をクリアします。その後は再登録が必要です。
- 1 つの AI クライアントだけを無効にするには、そのクライアントの MCP 構成から sctl を削除します。他の CLI やクライアントのアクセスは取り消されません。

## 7. トラブルシューティング {#troubleshooting}

**デーモンに到達できない**

最初に `sctl serve` を実行してください。要求コマンドはデーモンを自動起動しません。

**制御チャネルの認証に失敗する**

`serve`、CLI コマンド、MCP プロセスが同じ絶対データディレクトリを解決していることを確認します。`SCTL_DATA_DIR` と明示的な
`--data-dir` の両方を確認し、MCP クライアントを再起動します。

**ステータスに「接続に失敗しました」と表示される**

デーモンが実行されていること、拡張機能のアドレスが一致していること、ローカルのセキュリティソフトウェアが
`127.0.0.1:8643` をブロックしていないことを確認します。

**コマンドが返らない**

ブラウザにソース開示または書き込みの確認ページがないか確認してください。`Ctrl-C` を押して要求を無効にします。

**ログを見つける**

ログは `<data-dir>/logs/` の下にあります。`--data-dir` も `SCTL_DATA_DIR` も設定されていない場合のデフォルトは次のとおりです:

| プラットフォーム | ログディレクトリ |
|---|---|
| macOS | `~/Library/Application Support/sctl/logs/` |
| Windows | `%LOCALAPPDATA%\sctl\logs\` |
| Linux | `~/.config/sctl/logs/` |
